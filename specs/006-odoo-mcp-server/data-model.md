# Data Model: Odoo MCP Server

**Feature**: 006-odoo-mcp-server
**Date**: 2026-03-17
**Phase**: 1 (Design & Contracts)

## Overview

This document defines the data entities used by the Odoo MCP Server. Entities map to Odoo models and vault file structures.

---

## Entity 1: Invoice

**Purpose**: Represents a customer invoice with header information and line items.

**Odoo Model**: `account.move` (with `move_type='out_invoice'`)

### Fields

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| invoice_id | Integer | Yes (output) | Odoo invoice ID | Auto-generated by Odoo |
| invoice_number | String | Yes (output) | Invoice number (e.g., INV/2026/0001) | Auto-generated by Odoo |
| customer_id | Integer | Yes | Odoo partner ID | Must exist in res.partner |
| customer_name | String | Yes (output) | Customer name | From res.partner |
| invoice_date | Date | Yes | Invoice date | ISO 8601 format (YYYY-MM-DD) |
| due_date | Date | No | Payment due date | ISO 8601 format, defaults to invoice_date + 30 days |
| state | Enum | Yes | Invoice state | draft, posted, paid, cancel |
| line_items | Array | Yes | Invoice line items | Min 1 item, see LineItem entity |
| total_amount | Decimal | Yes (output) | Total invoice amount | Calculated by Odoo |
| amount_residual | Decimal | Yes (output) | Outstanding balance | Calculated by Odoo |
| currency_id | Integer | No | Currency | Defaults to company currency |
| ref | String | Yes | Reference/memo | Stores approval_id for idempotency |

### State Transitions

```
draft → posted → paid
  ↓
cancel
```

- **draft**: Editable, not finalized, can be modified or deleted
- **posted**: Finalized, immutable, sent to customer
- **paid**: Fully paid, no outstanding balance
- **cancel**: Cancelled invoice, no longer valid

### Relationships

- **customer_id** → `res.partner` (Many-to-One)
- **line_items** → `account.move.line` (One-to-Many)
- **payments** → `account.payment` (Many-to-Many via reconciliation)

### Business Rules

1. Invoice must have at least one line item
2. Customer must exist in Odoo before invoice creation
3. Draft invoices can be edited, posted invoices cannot
4. Total amount calculated automatically from line items
5. Invoice number generated automatically on posting
6. Approval required before posting (state: draft → posted)

### Example

```json
{
  "invoice_id": 123,
  "invoice_number": "INV/2026/0001",
  "customer_id": 45,
  "customer_name": "Acme Corp",
  "invoice_date": "2026-03-17",
  "due_date": "2026-04-16",
  "state": "posted",
  "line_items": [
    {
      "product_id": 10,
      "description": "Consulting Services",
      "quantity": 10,
      "unit_price": 100.00,
      "subtotal": 1000.00
    }
  ],
  "total_amount": 1000.00,
  "amount_residual": 1000.00,
  "ref": "approval_20260317_120000_invoice"
}
```

## Entity 2: Payment

**Purpose**: Represents a payment transaction against an invoice.

**Odoo Model**: `account.payment`

### Fields

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| payment_id | Integer | Yes (output) | Odoo payment ID | Auto-generated by Odoo |
| invoice_id | Integer | Yes | Invoice being paid | Must exist and be posted |
| amount | Decimal | Yes | Payment amount | Must be > 0 and ≤ amount_residual |
| payment_date | Date | Yes | Payment date | ISO 8601 format (YYYY-MM-DD) |
| payment_method | Enum | Yes | Payment method | cash, bank_transfer, check, credit_card |
| reference | String | No | Payment reference | Stores approval_id for idempotency |
| state | Enum | Yes | Payment state | draft, posted, reconciled |

### State Transitions

```
draft → posted → reconciled
```

- **draft**: Payment prepared, not recorded
- **posted**: Payment recorded in accounting
- **reconciled**: Payment matched to invoice

### Relationships

- **invoice_id** → `account.move` (Many-to-One)

### Business Rules

1. Invoice must be in 'posted' state before payment
2. Payment amount cannot exceed outstanding balance (FR-006)
3. Partial payments allowed (amount < amount_residual)
4. Approval required before recording payment (SR-002)
5. Payment automatically reconciles with invoice

### Example

```json
{
  "payment_id": 456,
  "invoice_id": 123,
  "amount": 500.00,
  "payment_date": "2026-03-20",
  "payment_method": "bank_transfer",
  "reference": "approval_20260320_140000_payment",
  "state": "reconciled"
}
```

## Entity 3: Customer

**Purpose**: Represents a business entity that receives invoices.

**Odoo Model**: `res.partner`

### Fields

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| customer_id | Integer | Yes | Odoo partner ID | Auto-generated by Odoo |
| name | String | Yes | Customer name | Max 255 characters |
| email | String | No | Email address | Valid email format |
| phone | String | No | Phone number | Any format |
| street | String | No | Street address | Max 255 characters |
| city | String | No | City | Max 255 characters |
| country_id | Integer | No | Country | Odoo country ID |

### Business Rules

1. Customer creation is OUT OF SCOPE (assumption: customers already exist)
2. Customer must exist before invoice creation
3. Customer lookup by ID or name

### Example

```json
{
  "customer_id": 45,
  "name": "Acme Corp",
  "email": "billing@acme.com",
  "phone": "+1-555-0100",
  "street": "123 Main St",
  "city": "New York"
}
```

## Entity 4: Line Item

**Purpose**: Represents a single product or service on an invoice.

**Odoo Model**: `account.move.line`

### Fields

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| line_id | Integer | Yes (output) | Odoo line ID | Auto-generated by Odoo |
| product_id | Integer | Yes | Odoo product ID | Must exist in product.product |
| description | String | No | Line description | Defaults to product name |
| quantity | Decimal | Yes | Quantity | Must be > 0 |
| unit_price | Decimal | Yes | Price per unit | Must be ≥ 0 |
| tax_ids | Array[Integer] | No | Applied taxes | Odoo tax IDs |
| subtotal | Decimal | Yes (output) | Line subtotal | Calculated: quantity × unit_price |

### Business Rules

1. Product must exist in Odoo before line item creation
2. Quantity must be positive
3. Subtotal calculated automatically
4. Taxes applied based on product configuration

### Example

```json
{
  "line_id": 789,
  "product_id": 10,
  "description": "Consulting Services - Project Alpha",
  "quantity": 10,
  "unit_price": 100.00,
  "tax_ids": [1],
  "subtotal": 1000.00
}
```

## Entity 5: Approval Request

**Purpose**: Represents a pending approval for invoice or payment operation.

**Storage**: Vault file in `Pending_Approval/` directory

**Format**: Markdown with YAML frontmatter

### Fields

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| approval_id | String | Yes | Unique approval ID | Format: approval_YYYYMMDD_HHMMSS_type |
| action_type | Enum | Yes | Action type | invoice_finalize, payment_record |
| odoo_invoice_id | Integer | Conditional | Invoice ID | Required for invoice_finalize |
| odoo_payment_id | Integer | Conditional | Payment ID | Required for payment_record |
| action_params | Object | Yes | Action parameters | Varies by action_type |
| risk_assessment | Enum | Yes | Risk level | low, medium, high |
| reasoning | String | Yes | Approval reasoning | Min 10 characters |
| created_at | DateTime | Yes | Creation timestamp | ISO 8601 format |
| status | Enum | Yes | Approval status | pending, approved, rejected |

### File Lifecycle

```
Pending_Approval/ → Approved/ → Done/
                 ↘ Rejected/ → Done/
```

### Business Rules

1. Approval ID must be unique
2. File movement triggers approval executor
3. Approved actions executed by approval_executor.py
4. Rejected actions logged but not executed
5. All actions logged to audit trail

### Example (invoice_finalize)

```markdown
---
approval_id: approval_20260317_120000_invoice_123
action_type: invoice_finalize
odoo_invoice_id: 123
action_params:
  invoice_id: 123
  customer_name: "Acme Corp"
  total_amount: "***"
  line_items_count: 3
risk_assessment: low
reasoning: "Standard customer invoice for completed project work"
created_at: 2026-03-17T12:00:00Z
status: pending
---

# Invoice Finalization Approval

**Customer:** Acme Corp
**Invoice ID:** 123
**Total Amount:** [MASKED]
**Line Items:** 3

## Actions Required

- [ ] Review invoice details
- [ ] Verify customer and amounts
- [ ] Move to Approved/ to finalize
- [ ] Move to Rejected/ to cancel
```

## Entity 6: Financial Report

**Purpose**: Represents aggregated financial data for a time period.

**Storage**: Generated on-demand, not persisted

### Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| report_type | Enum | Yes | Report type (revenue_summary, receivables, payment_collection) |
| period_start | Date | Yes | Report start date |
| period_end | Date | Yes | Report end date |
| total_revenue | Decimal | Yes | Total revenue (masked in logs) |
| paid_amount | Decimal | Yes | Total paid amount (masked in logs) |
| outstanding_balance | Decimal | Yes | Total outstanding (masked in logs) |
| invoice_count | Integer | Yes | Number of invoices |
| payment_count | Integer | Yes | Number of payments |

2. **receivables**: List of customers with outstanding balances

## Data Flow Diagrams

### Invoice Creation Flow

```
Claude Code
    ↓ create_invoice(customer_id, line_items)
MCP Server
    ↓ validate inputs
    ↓ create draft invoice in Odoo
    ↓ generate approval request
Vault (Pending_Approval/)
    ↓ human reviews
    ↓ moves to Approved/
Approval Executor
    ↓ finalize invoice in Odoo (draft → posted)
    ↓ log action
Vault (Done/)
```

### Payment Recording Flow

```
Claude Code
    ↓ record_payment(invoice_id, amount)
MCP Server
    ↓ validate invoice exists and is posted
    ↓ validate amount ≤ outstanding balance
    ↓ generate approval request
Vault (Pending_Approval/)
    ↓ human reviews
    ↓ moves to Approved/
Approval Executor
    ↓ record payment in Odoo
    ↓ reconcile with invoice
    ↓ log action
Vault (Done/)
```

### Query Flow (No Approval)

```
Claude Code
    ↓ list_invoices(filters)
MCP Server
    ↓ build Odoo domain filter
    ↓ query account.move
    ↓ mask financial amounts
    ↓ return results
Claude Code
```

## Validation Rules Summary

### Invoice Validation

- Customer ID must exist in Odoo
- At least one line item required
- All line items must have valid product IDs
- Quantities must be positive
- Dates must be valid ISO 8601 format

### Payment Validation

- Invoice ID must exist and be in 'posted' state
- Payment amount must be > 0
- Payment amount must be ≤ invoice outstanding balance
- Payment date must be valid ISO 8601 format
- Payment method must be valid enum value

### Query Validation

- Date ranges must be valid (from ≤ to)
- Customer ID must exist if provided
- Status must be valid enum value if provided
- Limit must be positive integer

## Error Handling

### Validation Errors

Return structured error response:
```json
{
  "status": "error",
  "error_type": "validation_error",
  "message": "Customer ID 999 does not exist in Odoo",
  "field": "customer_id",
  "value": 999
}
```

```json
{
  "status": "error",
  "error_type": "odoo_api_error",

  "payment_amount": "***",
  "outstanding_balance": "***"
}
```

## Data Masking Rules

Per SR-009, all financial amounts must be masked in audit logs.

**Masked Fields**:
- `total_amount`
- `amount_residual`
- `amount`
- `unit_price`
- `subtotal`
- `price_unit`
- All report financial totals

**Masking Implementation**:
```python
masked_value = "***"
```

**Not Masked**:
- Invoice numbers
- Customer names
- Dates
- Quantities
- Product descriptions
- Approval IDs
- Status values
